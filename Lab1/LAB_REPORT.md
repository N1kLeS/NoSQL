# Отчёт

## Version 0.10

### Что сделал:

- Пользователь хранится в bucket `users`: key — `userId`, value — JSON с профилем и настройками уведомлений.
- `userId` выбран ключом, потому что пользователь запрашивается по идентификатору без поиска по всем записям.
- Приложение сохраняет и читает данные через HTTP API Riak KV. Этот способ поддерживается используемой версией Riak и не требует устаревшего Java-клиента.
- Для отсутствующего пользователя возвращается `HTTP 404`, для некорректных данных — `HTTP 400` с сообщением на русском языке.
- Пользователь расширен настройками `emailNotifications`, `pushNotifications` и `orderStatusNotifications`. Настройки сохраняются внутри JSON пользователя в bucket `users`.
- Структуру Riak изменять не потребовалось: значение записи представляет собой JSON и не имеет фиксированной SQL-схемы.
- Старые записи без настроек продолжают читаться; для них все виды уведомлений по умолчанию отключены.
- История хранится в bucket `user-actions`: key — уникальный `actionId`, value — JSON с `userId`, типом действия и временем его совершения.
- Для поиска действий конкретного пользователя применяется secondary index `user_id_bin`. Он доступен, поскольку используемый Riak настроен с backend `leveldb`.
- Индекс возвращает ключи действий по `userId`, после чего приложение читает соответствующие записи. Полное сканирование ключей не используется.
- Реализованы добавление действия и получение истории пользователя в хронологическом порядке.
- Временные пользовательские сессии хранятся в bucket `sessions`: key — случайный `sessionId`, value — JSON с `userId`, `createdAt` и `expiresAt`.
- Срок действия проверяется приложением при чтении: сессия действительна, пока текущее время меньше `expiresAt`.
- Истёкшая сессия удаляется из Riak и отклоняется с `HTTP 410`. Повторное чтение удалённой сессии возвращает `HTTP 404`.
- Реализованы создание сессии с заданным временем жизни и получение действующей сессии.
- Профиль пользователя кэшируется по схеме cache-aside в bucket `profile-cache`: key — `userId`, value — профиль с `cachedAt` и `expiresAt`.
- При отсутствии записи выполняется `CACHE MISS`: профиль читается из основного bucket `users` и помещается в кэш. Повторное чтение даёт `CACHE HIT`.
- Истёкшая запись удаляется и заново загружается из основного представления. Срок жизни кэша по умолчанию составляет 60 секунд.
- При сохранении пользователя его старый кэш удаляется; также реализовано принудительное обновление профиля в кэше.
- Для счётчика посещений страницы истории используется Riak CRDT Counter: bucket type `page-visit-counters`, bucket `page-visits`, key `user-history`.
- Bucket type создан с `datatype=counter` и активирован. Команды сохранены в `scripts/init-counter-bucket-type.sh`.
- Каждое успешное получение истории пользователя выполняет атомарную операцию `increment`, а текущее значение доступно через `GET /api/page-visits/user-history`.
- Обычная схема «прочитать число, увеличить, записать» не используется, поэтому параллельные увеличения не теряются.
- Одного узла недостаточно для исследования отказа node, поэтому инфраструктура расширена до трёх узлов `riak@riak1.local`, `riak@riak2.local` и `riak@riak3.local`.
- Узлы имеют общий Erlang cookie и стабильные имена внутри Docker-сети. Для приложения основной HTTP endpoint остаётся `localhost:8098`; два других доступны на портах `8099` и `8100`.
- Узлы реально объединяются командами `cluster join`, `cluster plan` и `cluster commit` через `scripts/init-riak-cluster.sh`.
- Состав кластера и распределение кольца проверяются командами `member-status` и `ring-status`.
